# Atlas 200 DK A1 与 DHT11 云边协同实验操作指南

本指南对应课件第5～14页：先在华为云IEF中注册并纳管Atlas，再由Atlas采集DHT11数据，经MQTT传到电脑。电脑在本实验中模拟“云端”。所有命令在你实际连接开发板的那台电脑或SSH终端执行；本指南没有对开发板进行远程操作。

配套报告正文见《云边协同实验报告.md》，参考采集程序见 `dht11_reader.c`。程序没有经过你的Atlas与传感器实测，需按以下顺序验证。

## 1 先确定硬件和电平

这里指老款Atlas 200 DK，Ascend 310，40Pin排针，通常称A1。不是Atlas 200I DK A2。不要套用树莓派的BCM编号或A2教程。

先关闭开发板，断开电源后接线。按板上“1”脚丝印定位，针号排列为一排奇数1、3、5、7……，另一排偶数2、4、6、8……；不要根据开发板朝向猜1脚。

| DHT11模块丝印 | Atlas 40Pin物理针脚 | 说明 |
|---|---|---|
| VCC、+ | 1号 | 3.3V供电，17号也是3.3V |
| GND、− | 6号 | 公共地 |
| DATA、S、OUT | 7号GPIO0 | 官方老镜像软件全局编号504；接法见下述电平分支 |

三针模块的针序不统一，必须按丝印接。四针裸DHT11按器件手册识别VCC、DATA、NC、GND，NC不接。供电、信号不要接5V。

**GPIO0电平存在官方资料差异。** 华为40Pin硬件表把GPIO0列为3.3V；《外围设备驱动接口操作指南》又写直接引出的GPIO高电平为1.8V。因此，只有确认你这块板卡版本的外部7脚支持3.3V输入输出后，才能把DATA直接接7脚，并在DATA与3.3V间接4.7kΩ上拉电阻（模块已带上拉可不重复添加）。GPIO输出电压测量本身不能证明输入耐压。

如果板卡外部GPIO0是1.8V，用支持开漏单总线、1.8V↔3.3V的双向电平转换模块，按模块手册连接：

| 电平转换模块端子 | 连接 |
|---|---|
| LV | Atlas物理36号，1.8V |
| HV | Atlas物理1号，3.3V |
| GND | Atlas物理6号，并与DHT11的GND共地 |
| LV1 | Atlas物理7号GPIO0 |
| HV1 | DHT11 DATA |

DHT11 VCC仍接3.3V。两侧信号分别上拉到各自电源；许多电平转换模块已带电阻，以实际模块电路为准。不要用单向分压电阻代替双向转换。**电平未确认时先不要把DATA直接接GPIO。**

不要改接29/31/33/35/37号来避开电平问题：这些是PCA6416的I²C扩展GPIO，不适合本例的微秒脉冲捕获。

## 2 记录环境

上电后SSH登录Atlas，执行：

```bash
uname -m
uname -r
cat /etc/os-release
ip -4 addr
ls /dev/gpiochip*
```

记录架构、系统、内核和你实际SSH使用的Atlas IP。下文 `192.168.137.2` 只是例子，统一换成你的板子IP。

## 3 先做MQTT的hello world

### 3.1 在Atlas的SSH终端执行

```bash
sudo apt update
sudo apt install -y mosquitto mosquitto-clients build-essential
```

仅用于可信的实验局域网，配置匿名监听：

```bash
sudo tee /etc/mosquitto/conf.d/week8.conf >/dev/null <<'EOF'
listener 1883 0.0.0.0
allow_anonymous true
EOF
sudo systemctl enable --now mosquitto
sudo systemctl restart mosquitto
sudo ss -lntp | grep ':1883'
```

应看到 `0.0.0.0:1883`。Mosquitto 2默认仅监听本机，单纯安装后直接从电脑连接容易失败。此配置仅用于这次局域网实验，不要将1883映射到公网。

若服务重启失败，检查 `sudo journalctl -u mosquitto -n 40 --no-pager` 及已有的监听配置，避免重复配置同一端口。不需要在电脑启动第二个MQTT服务。

### 3.2 在电脑执行

Windows从 https://mosquitto.org/download/ 安装Mosquitto，使用其客户端即可。PowerShell中执行：

```powershell
& 'C:\Program Files\mosquitto\mosquitto_sub.exe' -h 192.168.137.2 -p 1883 -t 'test/topic' -v
```

保持窗口打开，再到Atlas执行：

```bash
mosquitto_pub -h 127.0.0.1 -p 1883 -t 'test/topic' -m 'hello world'
```

电脑出现 `test/topic hello world` 即表示链路正常。Linux或macOS电脑安装客户端后，使用相同的 `mosquitto_sub -h ...` 命令。

电脑收不到时，Windows先执行 `Test-NetConnection 192.168.137.2 -Port 1883`。检查IP、板端监听、网络和板端防火墙；若启用ufw，只放行电脑实际IP到1883端口，不必关闭整机防火墙。SSH连接成功不代表1883也已放行。

## 4 单独验证DHT11采集

将同目录 `dht11_reader.c` 上传到Atlas的 `/home/HwHiAiUser/week8/`。用户名或家目录不同就相应修改。可以用MobaXterm上传，也可以在电脑当前文件目录运行：

```bash
scp dht11_reader.c HwHiAiUser@192.168.137.2:/home/HwHiAiUser/
```

然后在Atlas编译（实际参数见程序开头的用法）：

```bash
cd /home/HwHiAiUser
gcc -O2 -Wall -Wextra -std=c11 dht11_reader.c -o dht11_reader
sudo ./dht11_reader --gpio 504 --count 10
```

采集器使用Linux GPIO字符设备v1的双边沿事件和内核时间戳，不依赖树莓派库，也不使用Python微秒sleep。它自动把官方镜像的全局GPIO504转换为gpiochip与line offset；**504不是gpiochip内偏移，也不是排针针号。** 程序默认每3秒尝试一次，仅将校验成功的数据输出为JSON；错误写到stderr。

读到数据后，把本地输出保存下来：

```bash
sudo ./dht11_reader --gpio 504 --count 10 > local.jsonl 2> sensor.log
cat local.jsonl
cat sensor.log
```

`--count 10` 的含义以程序帮助为准。JSON中的温湿度必须来自实测。不要将手工生成的MQTT测试消息记作传感器测量。

若程序提示504已被占用，确认没有其他采集进程。此前如果仅用sysfs手工导出了504，可在结束该用途后执行 `echo 504 | sudo tee /sys/class/gpio/unexport` 再试；不要释放其他程序正在使用的引脚。

如果没有 `/dev/gpiochip*`、请求事件返回 `Operation not supported`、持续没有完整数据或频繁校验失败：先核对接线、电平、上拉、短导线和模块型号，再看内核驱动是否支持GPIO0双边沿中断。此时需要课程提供的DHT11适配驱动，或由匹配该板内核的Linux DHT11 IIO驱动处理时序。本程序是参考实现，不能保证所有旧Atlas镜像均支持。不要通过随意换GPIO编号或增加温湿度常数绕过问题。Linux内核原生DHT11驱动还需配置GPIO及设备树，仅 `modprobe dht11` 不会自动识别接线。

## 5 把真实数据发到电脑

电脑先订阅并保存记录（PowerShell）：

```powershell
& 'C:\Program Files\mosquitto\mosquitto_sub.exe' -h 192.168.137.2 -p 1883 -t 'atlas/dht11' -q 1 -v | Tee-Object -FilePath .\mqtt_receive.txt
```

Atlas执行：

```bash
set -o pipefail
sudo ./dht11_reader --gpio 504 2>sensor.log | tee sent.jsonl | mosquitto_pub -h 127.0.0.1 -p 1883 -t 'atlas/dht11' -q 1 -l
```

`-l` 将标准输入的每行作为一条MQTT消息。Ctrl+C停止；`sent.jsonl`是采集器向发布工具提交的记录，电脑的 `mqtt_receive.txt` 是实际接收到的记录，二者可按seq对应。`sent.jsonl`本身不是云端接收成功的证据。

链路是：DHT11 → Atlas采集器 → Atlas上的Mosquitto → 电脑订阅器。发布器用127.0.0.1是因为Broker就在Atlas上；电脑连接的则是Atlas的实际IP。QoS 1可能重复投递，核对数据时按设备、运行标识和seq去重。

稳定采集后，可将手掌靠近传感器数厘米，观察变化，不要让传感器结露，也不要将其贴在发热芯片上。记录至少10条真实数据、采集失败情况，以及电脑与板端相同序号的数据。

## 6 完成课件的IEF纳管部分

这部分负责云端管理边缘节点；上面的MQTT实验使用独立Mosquitto，不会自动把数据送进IEF控制台。

1. 在华为云登录IEF，选择实验区域，完成服务授权。
2. 注册边缘节点，名称例如Atlas200DK。本实验不使用NPU资源，按课件选AI加速卡“不启用”；这不代表所有IEF资源都免费，开通前以控制台计费提示为准。
3. 下载 **arm64** 安装工具和该节点的配置包，版本用控制台当前提供的版本，不要强行下载课件旧版1.0.10。
4. 安装前检查 `docker -v`、`sudo docker info`、`timedatectl`，并确认板子可以访问互联网。已经SSH可达不代表板子能访问华为云。
5. 先按官方“配置边缘节点环境”检查Docker和系统支持。旧Ubuntu镜像若缺Docker，按其系统版本和IEF支持矩阵安装；不要为了本实验直接升级板卡内核或系统。
6. 使用证书注册方式时，上传两个包后执行下列命令；把安装器文件名换成实际名称：

```bash
cd /home/HwHiAiUser
sudo tar -zxvf edge-installer_实际版本_arm64.tar.gz -C /opt
sudo mkdir -p /opt/IEF/Cert
sudo tar -zxvf Atlas200DK.tar.gz -C /opt/IEF/Cert
cd /opt/edge-installer
sudo ./installer -op=install
```

新版安装器可先按控制台命令用 `edgectl diagnose installation` 诊断；端点使用所选区域的真实IEF云上端点。若选择token注册，按控制台生成的identifier命令执行，不套用证书包步骤。

7. IEF控制台显示节点“运行中”后截图。截图隐去证书、token和密码。不要将本实验独立MQTT的1883端口与IEF自带消息通道的8883证书连接混用。
